# 貢獻 Serelix_Bot

首先，感謝您考慮為 Serelix_Bot 做出貢獻！正是像您這樣的人讓這個專案變得偉大。

我們歡迎任何形式的貢獻，而不僅僅是程式碼。您可以透過以下方式提供幫助：
*   **回報錯誤**
*   **討論程式碼的當前狀態**
*   **提交修復**
*   **提出新功能**
*   **成為維護者**

## 我們使用 Github 進行開發
我們使用 Github 來託管程式碼、追蹤問題和功能請求，以及接受拉取請求。

## 所有程式碼變更都透過拉取請求進行
拉取請求是提議對程式碼庫進行變更的最佳方式。我們積極歡迎您的拉取請求：

1.  Fork 儲存庫並從 `main` 建立您的分支。
2.  如果您新增了應進行測試的程式碼，請新增測試。
3.  如果您變更了 API，請更新文件。
4.  確保測試套件通過。
5.  確保您的程式碼通過 lint 檢查。
6.  發出該拉取請求！

## 您做出的任何貢獻都將遵守 MIT 軟體授權
簡而言之，當您提交程式碼變更時，您的提交將被理解為受與專案相同的 [MIT 授權](http.choosealicense.com/licenses/mit/) 的約束。如果對此有疑慮，請隨時與維護人員聯繫。

## 使用 Github 的 [issues](https://github.com/git/git/issues) 回報錯誤
我們使用 GitHub issues 來追蹤公共錯誤。透過[開啟一個新 issue]()來回報錯誤；就這麼簡單！

## 編寫詳細、有背景和範例程式碼的錯誤報告
**優秀的錯誤報告**往往具有：

*   快速摘要和/或背景
*   重現步驟
    *   要具體！
    *   如果可以，請提供範例程式碼。
*   您期望發生什麼
*   實際發生了什麼
*   備註（可能包括您認為可能發生這種情況的原因，或者您嘗試過但沒有奏效的方法）

人們*喜歡*詳盡的錯誤報告。我不是在開玩笑。

## 使用一致的編碼風格
*   我們對 Python 程式碼使用 [PEP 8](https://www.python.org/dev/peps/pep-0008/)。
*   您可以嘗試執行 `black .` 來統一風格。
