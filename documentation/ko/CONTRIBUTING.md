# Serelix_Bot에 기여하기

먼저 Serelix_Bot에 기여하는 것을 고려해 주셔서 감사합니다! 이 프로젝트를 훌륭하게 만드는 것은 바로 여러분과 같은 사람들입니다.

코드뿐만 아니라 모든 종류의 기여를 환영합니다. 다음과 같은 방법으로 도울 수 있습니다:
*   **버그 보고**
*   **코드의 현재 상태에 대한 논의**
*   **수정 사항 제출**
*   **새로운 기능 제안**
*   **유지 관리자 되기**

## 우리는 Github로 개발합니다
우리는 코드를 호스팅하고, 문제 및 기능 요청을 추적하며, 풀 리퀘스트를 받기 위해 Github를 사용합니다.

## 모든 코드 변경은 풀 리퀘스트를 통해 이루어집니다
풀 리퀘스트는 코드베이스에 변경 사항을 제안하는 가장 좋은 방법입니다. 우리는 여러분의 풀 리퀘스트를 적극적으로 환영합니다:

1.  리포지토리를 포크하고 `main`에서 브랜치를 만듭니다.
2.  테스트해야 하는 코드를 추가했다면 테스트를 추가하십시오.
3.  API를 변경했다면 문서를 업데이트하십시오.
4.  테스트 스위트가 통과하는지 확인하십시오.
5.  코드가 린트(정적 분석)를 통과하는지 확인하십시오.
6.  풀 리퀘스트를 발행하십시오!

## 귀하가 하는 모든 기여는 MIT 소프트웨어 라이선스에 따라 이루어집니다
요컨대, 코드 변경 사항을 제출하면 귀하의 제출물은 프로젝트를 다루는 것과 동일한 [MIT 라이선스](http.choosealicense.com/licenses/mit/)에 따라 이해됩니다. 우려 사항이 있는 경우 유지 관리자에게 문의하십시오.

## Github의 [issues](https://github.com/git/git/issues)를 사용하여 버그를 보고하십시오
우리는 공개 버그를 추적하기 위해 GitHub issues를 사용합니다. 버그를 보고하려면 [새로운 issue를 여십시오](); 그렇게 쉽습니다!

## 버그 보고서는 세부 정보, 배경 및 샘플 코드로 작성하십시오
**훌륭한 버그 보고서**는 다음과 같은 경향이 있습니다:

*   간단한 요약 및/또는 배경
*   재현 단계
    *   구체적으로!
    *   가능하다면 샘플 코드를 제공하십시오.
*   예상했던 결과
*   실제로 일어나는 일
*   참고 (이것이 왜 발생한다고 생각하는지에 대한 내용이나 시도했지만 작동하지 않은 내용 포함)

사람들은 철저한 버그 보고서를 *사랑*합니다. 농담이 아닙니다.

## 일관된 코딩 스타일 사용
*   Python 코드에는 [PEP 8](https://www.python.org/dev/peps/pep-0008/)을 사용합니다.
*   스타일 통일을 위해 `black .`을 실행해 볼 수 있습니다.
