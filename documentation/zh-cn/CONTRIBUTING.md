# 贡献 Serelix_Bot

首先，感谢您考虑为 Serelix_Bot 做出贡献！正是像您这样的人让这个项目变得伟大。

我们欢迎任何形式的贡献，而不仅仅是代码。您可以通过以下方式提供帮助：
*   **报告错误**
*   **讨论代码的当前状态**
*   **提交修复**
*   **提出新功能**
*   **成为维护者**

## 我们使用 Github 进行开发
我们使用 Github 来托管代码、跟踪问题和功能请求，以及接受拉取请求。

## 所有代码更改都通过拉取请求进行
拉取请求是提议对代码库进行更改的最佳方式。我们积极欢迎您的拉取请求：

1.  Fork 仓库并从 `main` 创建您的分支。
2.  如果您添加了应进行测试的代码，请添加测试。
3.  如果您更改了 API，请更新文档。
4.  确保测试套件通过。
5.  确保您的代码通过 lint 检查。
6.  发出该拉取请求！

## 您做出的任何贡献都将遵守 MIT 软件许可证
简而言之，当您提交代码更改时，您的提交将被理解为受与项目相同的 [MIT 许可证](http.choosealicense.com/licenses/mit/) 的约束。如果对此有疑虑，请随时与维护人员联系。

## 使用 Github 的 [issues](https://github.com/git/git/issues) 报告错误
我们使用 GitHub issues 来跟踪公共错误。通过[开启一个新 issue]()来报告错误；就这么简单！

## 编写详细、有背景和示例代码的错误报告
**优秀的错误报告**往往具有：

*   快速摘要和/或背景
*   重现步骤
    *   要具体！
    *   如果可以，请提供示例代码。
*   您期望发生什么
*   实际发生了什么
*   备注（可能包括您认为可能发生这种情况的原因，或者您尝试过但没有奏效的方法）

人们*喜欢*详尽的错误报告。我不是在开玩笑。

## 使用一致的编码风格
*   我们对 Python 代码使用 [PEP 8](https://www.python.org/dev/peps/pep-0008/)。
*   您可以尝试运行 `black .` 来统一风格。

## 许可证
通过贡献，您同意您的贡献将根据其 MIT 许可证进行许可。
