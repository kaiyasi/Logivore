# Вклад в Serelix_Bot

Прежде всего, спасибо за то, что вы рассматриваете возможность внести свой вклад в Serelix_Bot! Именно такие люди, как вы, делают этот проект великолепным.

Мы приветствуем любой вклад, а не только код. Вы можете помочь:
*   **Сообщив об ошибке**
*   **Обсудив текущее состояние кода**
*   **Отправив исправление**
*   **Предложив новые функции**
*   **Став сопровождающим**

## Мы разрабатываем с помощью Github
Мы используем Github для размещения кода, отслеживания проблем и запросов на новые функции, а также для приема запросов на слияние.

## Все изменения в коде происходят через запросы на слияние
Запросы на слияние — лучший способ предложить изменения в кодовой базе. Мы активно приветствуем ваши запросы на слияние:

1.  Сделайте форк репозитория и создайте свою ветку из `main`.
2.  Если вы добавили код, который должен быть протестирован, добавьте тесты.
3.  Если вы изменили API, обновите документацию.
4.  Убедитесь, что набор тестов проходит.
5.  Убедитесь, что ваш код проходит проверку линтером.
6.  Отправьте этот запрос на слияние!

## Любой ваш вклад будет осуществляться под лицензией MIT Software License
Короче говоря, когда вы отправляете изменения в коде, ваши материалы считаются находящимися под той же [лицензией MIT](http.choosealicense.com/licenses/mit/), которая распространяется на проект. Не стесняйтесь обращаться к сопровождающим, если это вас беспокоит.

## Сообщайте об ошибках, используя [issues](https://github.com/git/git/issues) Github
Мы используем GitHub issues для отслеживания публичных ошибок. Сообщите об ошибке, [открыв новый issue](); это так просто!

## Пишите отчеты об ошибках с подробностями, предысторией и примерами кода
**Отличные отчеты об ошибках**, как правило, содержат:

*   Краткое резюме и/или предысторию
*   Шаги для воспроизведения
    *   Будьте конкретны!
    *   Если можете, предоставьте пример кода.
*   Что вы ожидали, что произойдет
*   Что происходит на самом деле
*   Примечания (возможно, включая то, почему, по вашему мнению, это могло произойти, или то, что вы пробовали, но не сработало)

Люди *любят* подробные отчеты об ошибках. Я даже не шучу.

## Используйте последовательный стиль кодирования
*   Мы используем [PEP 8](https.python.org/dev/peps/pep-0008/) для кода на Python.
*   Вы можете попробовать запустить `black .` для унификации стиля.

## Лицензия
Внося свой вклад, вы соглашаетесь с тем, что ваши вклады будут лицензироваться в соответствии с его лицензией MIT.
