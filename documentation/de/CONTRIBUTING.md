# Beitrag zu Serelix_Bot

Zunächst einmal vielen Dank, dass Sie in Erwägung ziehen, zu Serelix_Bot beizutragen! Es sind Leute wie Sie, die dieses Projekt großartig machen.

Wir begrüßen jede Art von Beitrag, nicht nur Code. Sie können helfen bei:
*   **Melden eines Fehlers**
*   **Diskussion über den aktuellen Stand des Codes**
*   **Einreichen einer Korrektur**
*   **Vorschlagen neuer Funktionen**
*   **Betreuer werden**

## Wir entwickeln mit Github
Wir verwenden Github, um Code zu hosten, Probleme und Funktionswünsche zu verfolgen und Pull-Anfragen anzunehmen.

## Alle Code-Änderungen erfolgen über Pull-Anfragen
Pull-Anfragen sind der beste Weg, um Änderungen an der Codebasis vorzuschlagen. Wir freuen uns über Ihre Pull-Anfragen:

1.  Forken Sie das Repo und erstellen Sie Ihren Branch von `main`.
2.  Wenn Sie Code hinzugefügt haben, der getestet werden sollte, fügen Sie Tests hinzu.
3.  Wenn Sie APIs geändert haben, aktualisieren Sie die Dokumentation.
4.  Stellen Sie sicher, dass die Testsuite erfolgreich ist.
5.  Stellen Sie sicher, dass Ihr Code den Linter-Prüfungen entspricht.
6.  Stellen Sie die Pull-Anfrage!

## Alle Ihre Beiträge unterliegen der MIT-Softwarelizenz
Kurz gesagt, wenn Sie Code-Änderungen einreichen, wird davon ausgegangen, dass Ihre Einreichungen unter derselben [MIT-Lizenz](http.choosealicense.com/licenses/mit/) stehen, die das Projekt abdeckt. Wenden Sie sich an die Betreuer, wenn dies ein Problem darstellt.

## Melden Sie Fehler über Githubs [issues](https://github.com/git/git/issues)
Wir verwenden GitHub-Issues, um öffentliche Fehler zu verfolgen. Melden Sie einen Fehler, indem Sie ein [neues Issue eröffnen](); so einfach ist das!

## Schreiben Sie Fehlerberichte mit Details, Hintergrund und Beispielcode
**Großartige Fehlerberichte** haben in der Regel:

*   Eine kurze Zusammenfassung und/oder Hintergrund
*   Schritte zur Reproduktion
    *   Seien Sie spezifisch!
    *   Geben Sie Beispielcode an, wenn Sie können.
*   Was Sie erwartet hätten
*   Was tatsächlich passiert
*   Hinweise (möglicherweise auch, warum Sie glauben, dass dies passieren könnte, oder Dinge, die Sie ausprobiert haben und die nicht funktioniert haben)

Die Leute *lieben* ausführliche Fehlerberichte. Das ist kein Scherz.

## Verwenden Sie einen einheitlichen Codierungsstil
*   Wir verwenden [PEP 8](https://www.python.org/dev/peps/pep-0008/) für Python-Code.
*   Sie können versuchen, `black .` für eine Stilvereinheitlichung auszuführen.

## Lizenz
Durch Ihren Beitrag stimmen Sie zu, dass Ihre Beiträge unter der MIT-Lizenz lizenziert werden.
